01

每帧都是算出来的

GrokBotMark 在 JS 里维护一棵虚拟 SVG 节点树，每帧重新计算所有图形参数， 再由一个 DOM diff 写入器把变化落到真实 DOM：结构不变时只写 attribute，结构变了才 createElementNS 重建。

身体是 <path fill>；眼睛不是盖在身体上的白色形状，而是从身体上挖出来的洞——所以身体下面是 什么背景，眼睛就透出什么背景。挖洞有两条路：sphere 模式下直接把眼睛的地平线弧 布尔裁剪进身体 path；morph 状态下改用 SVG <mask>。

右侧属性面板实时显示当前帧的 path d 片段与各层 transform， 并用 MutationObserver 聚合每帧的真实 DOM 写入。打开「显示 DOM diff」 可以看到：idle 时每帧只有一次写入——身体 path[d] （眼睛的裁切弧就长在这条 path 里，所以它的长度随眼神逐帧变化）。

02

形状 morph：径向轮廓插值

怎么把圆形「变成」爱心？GrokBotMark 的做法是向 192 个角度方向发射线， 求每条射线与形状轮廓的交点，得到一个半径数组 r(θ)。 morph 就是对两个形状的 r(θ) 逐角度线性插值， 插值权重由弹簧驱动——所以形变本身也带物理感。

原引擎的形状注册表有 20+ 种（cloud / square / sparkle / clover / heart / star6 / teardrop / house / gem / egg / capsule…），但公开 API 只暴露 blob / flower / heart / star 四种。

右边拖 slider：圆形 → 六角星 → 爱心 → 水滴连续混合。打开「显示采样射线」可以看到 射线和交点；把采样数从 192 降到 8，看插值质量如何崩坏——采样密度就是这套方案的精度旋钮。

03

弹簧，不是定时器

引擎里没有任何 setTimeout 动画，也没有 CSS transition。所有运动来自一个 手写的半隐式欧拉弹簧积分器，以 120Hz 固定子步推进：

v += (-2ζω·v - ω²·(x - target))·dt
x += v·dt

只调两个参数——刚度 ω 和阻尼 ζ——就能得到从 Q 弹到稳重的全部质感。 而传统的 ease-out 曲线是时间的函数：中途改变目标，它只能生硬跳变；弹簧只要改 target，速度天然连续。

零第三方动画库：没有 framer-motion，没有 gsap。

04

伪 3D：眼睛真的在球面上

头部姿态是一组完整的旋转（原引擎用四元数存 pitch/yaw/roll）。眼睛不是贴在脸上的贴图： 眼睛脊线上的点绕球心做 3D 旋转，再正交投影到屏幕；转到背面的部分直接裁掉 ——眼睛真的会绕到球后面消失。

靠近边缘的眼睛被球面几何自然压缩：逆向时实测远侧眼宽 ≈ 近侧的 0.69 倍，这正是球面深度系数，不是手调的 hack。

右边拖拽球体旋转头部。切换「平面贴眼」看看常见省事方案什么样： 眼睛等宽平移、滑出边缘也不消失——瞬间就假了。

转动头部，观察两只眼睛宽度比变化

05

眨眼与生命感

眨眼不是独立调度器，而是写在 clip 里的关键帧事件：clip 的 expression 轨道上 一个 v:"blink" 事件会被编译器展开成三段 lids 关键帧——睁开 → 0.26×0.45 秒处完全闭合 → 0.26 秒处重新睁开，缓动 [.42,0,.58,1]。 眼睑把眼睛纵向压扁成细 stadium（胶囊）。

除 clip 内嵌事件外，还有两个来源：命令式 blink() 调用（用户交互触发）， 以及 through-blink 的表情切换（先闭眼再换表情睁开）。经逐行核对原 bundle： 不存在环境自动眨眼调度器——全 bundle 唯一的 Math.random 在网络重试退避里，与动画无关。「随机的外表」其实来自别处：idle 的 clip 洗牌（见下一节）。

右边是从提取数据 grok-recipes.json 直接画出的三条 idle clip 时间轴， 竖条 = 该 clip 内嵌的眨眼事件（Idle_D 里 2.07s 与 2.37s 那对就是一组双眨）。 上方是跑着真引擎的 bot；也可以点按钮手动触发一次 blink()。

06

状态机与 recipe 洗牌

原引擎的状态注册表有 53 个状态（idle / listening / thinking / blocked / finished / waking…）。每个状态 = 若干条手工关键帧 recipe（position / rotation / squash / lids / expression 轨道，每段独立三次贝塞尔缓动）。

idle 播放时种子化洗牌抽取下一条 clip、随机相位起播——所以待机永不重复。 next + holdSeconds 支持自动转移（如 blocked 持续 120 秒 → drowsy）； 尺寸小于 48px 时自动切换精简动画。

功能状态 = 身体缩小让位 + 程序化装饰图元。右边从 53 个状态里选了 7 个代表： idle / listening / thinking / waiting / alerting / working / finished——点哪个播哪个， 下方显示状态机当前真实播放的 clip。

这些动画是原版引擎的忠实移植（grok-player）+ 从本机 app 提取的原版动画数据， 不再是简化重实现。idle 的 clip 池、洗牌与相位全部由移植引擎内的种子化 PRNG 驱动。

08

看不见的工程细节

动画引擎的高级感，一半来自这些没人注意的角落：

  • requestAnimationFrame 驱动，60fps 上限节流
  • document.hidden 时暂停整个循环
  • IntersectionObserver 离屏停帧——看不见的 bot 不耗 CPU
  • 动画静止后自动休眠，事件到来再唤醒
  • prefers-reduced-motion 时完全静态
  • DOM diff 写入器：结构不变只写 attribute，变了才重建节点
  • 尺寸 < 48px 自动切精简动画

本页面自身就是这套哲学的实践：0 第三方运行时依赖、0 构建， 纯 HTML + CSS + 原生 ES modules；hero 与 01/05/06 节的 bot 运行原版引擎的移植 （js/vendor/grok-player.js）与从本机 app 提取的动画数据 （js/vendor/grok-recipes.json），其余 demo 实时计算， 全部遵守离屏休眠与 reduced-motion。
