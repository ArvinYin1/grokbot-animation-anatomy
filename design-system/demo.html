25 个头像形状，是怎么被造出来的

没有美术资源，没有贴图。每个形状都是几个数字加一条参数化轮廓算法。 这一页拆开整个流水线：从参数到轮廓，从轮廓到可动画的 SVG path。

25 个形状 可交互 阅读约 20 分钟

全景流水线

从一个形状名字到屏幕上会动的头像，只经过四步。每一步都是纯函数， 没有隐藏状态——这就是整个系统能被一页讲清楚的原因。

01

参数

每个形状由 4–8 个数字描述：半径、扁率、缺口角度。

02

轮廓算法

三种算法之一把参数变成闭合轮廓：圆角多边形、椭圆缺口、球链。

03

凸包约束

轮廓必须是凸的，否则眼睛座（eye seat）无法稳定贴合。

04

SVG Path

轮廓采样成贝塞尔路径，交给你熟悉的 fill 和 transform。

三种轮廓算法

25 个形状看起来千姿百态，其实只由三种算法生成。其中圆角多边形 承担了 18 个形状——它是这个系统的绝对主力。

engine/shape.js 
// 圆角多边形：顶点插值 + 角点圆弧
function roundedPoly(verts, r) {
  const path = [];
  for (let i = 0; i < verts.length; i++) {
    const [p0, p1, p2] = neighbors(verts, i);
    path.push(arc(p0, p1, p2, r)); // 每个角一段二次贝塞尔
  }
  return close(path);
}

关键直觉：所谓的"3D 光泽"并不来自轮廓，而是 fill 上的径向渐变加 halo。 同一个轮廓，换一套 fill 参数，就从扁平变成玻璃质感。

凸包约束

系统里唯一一条硬性几何规则：轮廓必须保持凸性。 一旦凹陷，眼睛座会陷入轮廓内部，眨眼动画就会穿帮。

常见坑：手动拖顶点时很容易无意中制造凹点。 工作台里的实时凸性判定（verdict bar）就是为这个问题而生的。
